# Правила разработки LogistAI

Документ обязателен к прочтению перед первым коммитом — даже если разработчик один.
Дисциплина закладывается сейчас, пока проект маленький.

## Быстрый старт

```bash
uv sync                                            # окружение + dev-зависимости
mv pre-commit-config.yaml .pre-commit-config.yaml  # однократно (см. примечание в файле)
uv run pre-commit install                          # git-хуки (однократно, обязательно)
uv run python main.py                              # запуск приложения
```

## Инструменты качества — все обязательны

| Команда | Что проверяет |
|---|---|
| `uv run ruff format .` | форматирование |
| `uv run ruff check .` | линтер |
| `uv run mypy` | типы (strict) |
| `uv run lint-imports` | архитектурные контракты (направление зависимостей) |
| `uv run pytest` | тесты |

Всё это запускается автоматически: pre-commit — на каждом коммите, CI — на каждом
push и pull request. **Коммит не проходит хук — чините причину, а не обходите её:
`git commit --no-verify` в проекте запрещён.**

## Правила архитектуры

Полное описание — в [ARCHITECTURE.md](ARCHITECTURE.md). Краткая матрица импортов:

| Пакет | Можно импортировать | Нельзя |
|---|---|---|
| `app/core` | только stdlib | всё остальное из `app` |
| `app/buses` | `core` | services, infrastructure, ui, plugins |
| `app/services` | `core`, `buses` | infrastructure, ui, plugins |
| `app/infrastructure` | `core` | services, ui, plugins |
| `app/ui` | `core`, `services`, `buses` | infrastructure, plugins, container |
| `app/plugins` | `core`, `buses` | services, infrastructure, ui |
| `bootstrap` / `container` | всё (composition root) | — |

Матрица закреплена контрактами import-linter в `pyproject.toml` — нарушение
валит CI. Менять контракты можно только осознанным решением с новым ADR.

Правило потоков: **изменения — через команды (CommandBus), факты — через события
(EventBus), чтение — query-методами сервисов.**

## Стиль кода

- Python 3.13+, PEP 8 через ruff (строка ≤ 100).
- Полная типизация: mypy strict — без `# type: ignore` без письменного обоснования в комментарии.
- Докстринги на русском: у каждого модуля, класса и публичного метода.
- Файл — одна зона ответственности, ориентир ≤ 300 строк.
- Никаких `print()` — только `logging`.
- Никаких глобальных переменных и синглтонов — зависимости через конструктор.
- Исключения не глотаются молча: либо обрабатываются осмысленно, либо пробрасываются.

## Версия

Единственный источник версии — файл `VERSION`. pyproject читает его через
hatchling, приложение — через `BuildInfo`. Хардкодить версию где-либо ещё запрещено.

## Тесты

- Новый код — с тестами (unit для ядра/сервисов, смоук для UI).
- Предпочитайте фейки (свои реализации портов) мокам.
- UI-тесты — offscreen (`QT_QPA_PLATFORM=offscreen`, ставится в conftest).

## Процесс: этапы и ревью-гейты

Разработка идёт этапами (см. docs/roadmap). Каждый этап завершается гейтом:

1. code review (читаемость, дубли, размеры файлов);
2. проверка архитектуры (направление зависимостей);
3. SOLID-чек новых классов;
4. проверка расширяемости;
5. поиск потенциальных багов (края, таймауты, отсутствие сети);
6. рефакторинг + повторный прогон всех проверок.

На гейте обновляются ARCHITECTURE.md и, при архитектурных решениях, ADR
(шаблон: `docs/adr/0000-template.md`).

## Коммиты

Conventional Commits: `feat:`, `fix:`, `refactor:`, `docs:`, `test:`, `chore:`.
Коммиты маленькие и атомарные — один коммит = одно смысловое изменение.
