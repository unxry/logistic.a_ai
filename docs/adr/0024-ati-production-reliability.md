# ADR-0024: ATI Production Reliability

- **Статус:** Принято
- **Дата:** 2026-07-31

## Контекст

Интеграция ATI (ADR-0023) работает, но до реальной эксплуатации оставались
риски: поведение на больших объёмах, хрупкость к изменению формата API,
повторные предложения с изменившейся ценой, спам уведомлениями при простое
источника, отсутствие эксплуатационных метрик. Архитектуру не меняем; все
улучшения — через существующие порты и сервисы.

## Решение

1. **Нагрузочная валидация.** Тест `test_ati_load.py` и воспроизводимый
   `scripts/cargo_pipeline_benchmark.py`: 1000 payload'ов ATI через весь
   конвейер (auth → пагинация → mapper → normalizer → дедуп → repository →
   search → matching → notification). Замер: ~365 мс на 1000 грузов
   (0.37 мс/груз), пик памяти 3.5 МиБ, 142 дубля отсеяны, 858 совместимых,
   лучший груз выбран корректно, trace_id сквозной. Пороговые ассерты
   зафиксированы в тесте (30 с / 256 МиБ — с большим запасом).
2. **Контрактные фикстуры** (`tests/fixtures/ati/`): обычный груз, без
   цены, без веса, нестандартные единицы («5.5 тонн», «620x245x250»,
   «120 000 руб»), пустые поля, ИЗМЕНЁННЫЙ формат API, 401, 429. Инвариант
   закреплён тестами: mapper никогда не бросает — нераспознанные данные
   дают Cargo с None-полями и предупреждение, полный payload остаётся в
   ``raw`` (после смены формата данные восстановимы новым маппингом).
   Комбинированные габариты больше не получают навязанную единицу — «6.2»
   и «620» различает эвристика нормализатора (метры < 20).
3. **CargoDeduplicationService** (замена простого фингерпринта в
   пайплайне): идентичность = ``source_id|external_id``, снапшот
   цена/маршрут/вес. Тот же снапшот — DUPLICATE; изменившийся — UPDATED:
   публикуется новое ядро-событие **CargoUpdated** (source_id, cargo,
   changes) и груз снова проходит подбор — подорожавший груз может стать
   лучшим. LRU 5000 идентичностей. Ограничение: изменение ДАТЫ погрузки не
   отслеживается, пока в модели Cargo нет поля даты (появится вместе с
   расширением модели; дата сохраняется в raw и attributes маппера).
4. **NotificationCooldownPolicy** (`services/notifications`, окно 180 с):
   повторные failure-уведомления источника в окне подавляются — «ATI упал»
   в 10:00/10:01/10:02 даёт ОДНО сообщение. Переход FAILED→ONLINE шлёт
   «🟢 Источник восстановлен» и сбрасывает cooldown — следующая авария
   уведомит немедленно. Политика общая (ключи выбирает вызывающий).
5. **Production-метрики SourceHealth** (аддитивно):
   ``last_success_duration_ms``, ``cargos_per_hour`` (0 до первой минуты
   работы — мало данных), ``duplicate_rate`` (доля дублей по данным
   пайплайна через инжектированный провайдер), ``error_rate``
   (failed/total); ``average_duration_ms`` — средний отклик. Наружу — через
   существующий контракт ``SourceStatusViewModel``: новые поля
   ``throughput`` («68 грузов/ч») и ``reliability`` («отклик 850 мс ·
   ошибки 2% · дубли 21%»); золотые снапшоты обновлены осознанно.
6. **Security-аудит** — закреплён тестами: секретов в коде нет (греп-тест),
   токен не попадает в логи и в тексты доменных ошибок (тела ответов API
   не эхо-копируются — только статус), заголовки не логируются, Keychain —
   единственный путь секретов (SourceCredentialProvider).

## Последствия

(+) Конвейер подтверждённо держит 1000+ грузов за доли секунды при
крошечной памяти; изменение формата ATI деградирует мягко (данные не
теряются); обновления цен становятся событиями; простой источника не
спамит; у эксплуатации есть метрики пропускной способности и надёжности.
(−) Дедупликация и cooldown живут в памяти процесса (перезапуск забывает
отпечатки — первое обновление после рестарта придёт как NEW; персистентная
дедупликация в SQLite — при необходимости, вместе с хранилищем грузов);
изменение даты погрузки не классифицируется до появления поля в Cargo.

## Готовность к реальному ATI

Код готов к подключению боевого API: секреты — Keychain, конфигурация —
sources.json, эндпоинты и маппинг — константы `client.py`/`mapper.py`
(единственное место правок при расхождении контракта), устойчивость к
ошибкам/лимитам/таймаутам и объёмам подтверждена тестами. Требуется только
живой ключ ATI и, при необходимости, точечная сверка имён полей ответа.
