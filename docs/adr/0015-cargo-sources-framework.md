# ADR-0015: Cargo Sources Framework

- **Статус:** Принято
- **Дата:** 2026-07-31

## Контекст

Нужен платформенный слой источников: ATI (API/браузер), Ozon, WB, CSV, плагины
должны подключаться без изменения Search Engine, Scheduler, Notification Center
и UI. Реализация конкретных источников — Stage 5.1+.

## Решение

1. **Источник = данные + корутина** (симметрично Job, ADR-0014): порт
   `CargoSource` → `spec: SourceSpec` + `fetch(context) → SourceResult`.
   Транспорт (httpx, Playwright, файлы) — деталь реализации в инфраструктуре;
   его замена не меняет контракт. Ошибки — только семейство `SourceError`
   (Authentication/Network/Parsing/RateLimit/Unavailable).
2. **SourceSpec** несёт `SourceCapabilities` (9 флагов: вес, габариты, объём,
   регионы, температура, паллеты, цена, live, документы) — Stage 6 по ним
   поймёт доступные фильтры; расписание и ретраи — переиспользуют
   `JobSchedule`/`JobRetryPolicy`.
3. **RawCargo → CargoNormalizer → Cargo.** Источники отдают «сырые» строки
   («5 тонн», «13.6», «москва»); нормализатор — единственное место конверсии
   единиц (кг/тонны, см/метры, м³), категорий, типов кузова и регионов.
   Непарсибельное → None: проверка совместимости предупредит, а не отбросит.
   Эвристики единиц зафиксированы тестами.
4. **SourceRuntime** — исполнитель: таймаут+ретраи по политикам из spec,
   нормализация, здоровье (ONLINE/DEGRADED/FAILED/DISABLED, порог 0.8),
   метрики-снапшоты, журнал (SOURCE_EVENT, trace_id), события
   (Started/Completed/Failed/HealthChanged/**CargoReceived** — вход Stage 6),
   уведомления об ошибках через `NotificationSender` (Telegram неизвестен).
5. **Scheduler-интеграция** — тонкий `SourcePollJob` (job `source:<id>`,
   расписание из spec): политики источника НЕ дублируются в job.
6. **SourceRegistry** — регистрация/удаление без if-ов, событие
   SourceRegistered; плагины используют существующий
   `PluginExtensions.add_source`.

## Альтернативы

- Источник сразу возвращает Cargo — каждый источник дублировал бы парсинг
  единиц; ошибки нормализации были бы размазаны и нетестируемы.
- Источник сам шлёт уведомления/пишет журнал — связность и дубли; вся
  наблюдаемость централизована в runtime.

## Последствия

(+) Новый источник = один класс + регистрация (проверено стабом в тестах);
Playwright/httpx останутся только в infrastructure; CargoReceived готов как
вход Search Engine. (−) Эвристики единиц без меток («5» → тонны) — осознанный
компромисс до реальных данных ATI; дедупликация грузов между источниками —
задача Stage 6.
