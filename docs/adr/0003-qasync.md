# ADR-0003: qasync — единая петля asyncio + Qt

- **Статус:** Принято
- **Дата:** 2026-07-31

## Контекст

Сетевые операции (Telegram Bot API, будущие источники) должны быть асинхронными
(ТЗ: asyncio + httpx), UI — не замерзать. Qt имеет собственный event loop.

## Решение

qasync: event loop asyncio интегрируется в петлю Qt — весь код (UI, сервисы,
планировщик, httpx) живёт в одном потоке.

## Альтернативы

- **QThread + сигналы** — классика Qt, но две модели конкурентности, ручные мосты,
  риск гонок; httpx.AsyncClient не используется естественно.
- **Отдельный поток с asyncio-петлёй** — мосты `call_soon_threadsafe` в обе стороны,
  сложнее отлаживать.
- **Синхронные вызовы + пул потоков** — блокировки и таймауты расползаются по коду.

## Последствия

(+) Нет гонок и блокировок UI; `async def` сервисы вызываются из ViewModel напрямую;
EventBus безопасен без локов.
(−) Зависимость от сопровождения qasync — изолирована в `bootstrap.py`
(одна точка замены); долгие CPU-задачи по-прежнему нужно уносить в `asyncio.to_thread`.
