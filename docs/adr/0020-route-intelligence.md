# ADR-0020: Route Intelligence — маршруты и реальная экономика рейса

- **Статус:** Принято
- **Дата:** 2026-07-31

## Контекст

Прибыль считалась плоско: (плечо + холостой пробег) × ₽/км. Реальная выгода
груза зависит от маршрута: фактическая дистанция и время в пути, платные
участки, топливо, оплата водителя, подгон под загрузку. Карты подключать
рано (ТЗ запрещает реальные API), но архитектура должна быть готова принять
OSRM / Яндекс / Google / HERE без переписывания движка.

## Решение

1. **Домен** (`core/models/routes`): `RouteEstimate` (геометрия + разбивка
   денег + confidence 0–100), `Route` (запись факта расчёта для событий и
   аналитики), `RouteCostPolicy` (тарифы пользователя; валидация в
   `__post_init__`).
2. **Порт `RouteProvider`** — асинхронный `calculate_route(origin,
   destination) -> RouteEstimate | None`. Провайдер знает ГЕОМЕТРИЮ
   (расстояние, время, уверенность, платные — если API отдаёт); деньги
   досчитывает сервис. Это сохраняет контракт «инфраструктура не знает про
   сервисы»: адаптерам не нужны настройки экономики. Пока —
   `MockRouteProvider` (детерминированная таблица направлений, симметричный
   поиск, незнакомое → `None`).
3. **`RouteCostCalculator`** (`services/routes`): топливо по формуле ТЗ
   «км / расход(км/л) × цена», реализованной в эквивалентной точной форме
   «литры × цена» (Decimal без погрешности деления; эквивалентность закрыта
   тестом); платные ₽/км (стоимость от провайдера точнее тарифа — берётся
   она); обслуживание ₽/км; водитель ₽/ч. total_trip_cost = топливо + платные
   + водитель + обслуживание. Холостой прогон = топливо + износ.
4. **`RouteService`**: кэш процесса (ограничен), событие `RouteCalculated`
   (один раз на расчёт, кэш не публикует), синтетическая оценка по расстоянию
   из объявления, когда провайдер молчит (confidence 40, время по средней
   скорости из политики, без события), стоимость холостого подгона
   «текущая точка → загрузка» (неизвестно — честный 0).
5. **`ProfitAnalysis`** вместо `ProfitEstimate`: gross_profit, разбивка
   (топливо/платные/водитель/обслуживание/холостой прогон), expenses,
   net_profit, profit_per_km, profit_per_hour. Событие `ProfitCalculated`
   на каждый расчёт.
6. **Matching v2**: веса 30% совместимость · 30% прибыль · 20% эффективность
   маршрута · 10% предпочтения · 10% свежесть; `MatchingWeights` валидируется
   (сумма 1.0) и конфигурируется (`settings.matching`); `MatchingContext.
   route_estimate` (при ранжировании подставляется per-cargo); сервис стал
   асинхронным (провайдеры — HTTP). Кривая свежести — общая функция ядра
   (`core/models/scoring.py`), используется и поиском.
7. **Настройки схемы 2**: секции `routing` (`RouteCostPolicy`) и `matching`
   (`MatchingWeights`) — доменные модели напрямую; миграция 1 → 2 создаёт
   пустые секции (дефолты — у моделей); мусор в JSON толерантно заменяется
   дефолтами.
8. **Аналитика**: `MatchingDecision.distance_km` (SQLite схема v3 — ALTER
   TABLE), чистая `summarize_routes` → `RouteAnalytics` (средняя дистанция,
   средняя ₽/км, best/worst направления); порт `MatchingRepository.
   route_statistics()`; счётчики маршрутов и ₽/км в `AnalyticsCollector`;
   строка «Средняя ставка ₽/км» в дневном отчёте.
9. **Уведомление категории ROUTE**: «🚚 Лучший груз найден» с экономикой —
   маршрут, расстояние, доход, расходы, чистая прибыль, ₽/км, причины.

Эталон дефолтов (закрыт тестами): Москва → Санкт-Петербург, 710 км / 10 ч →
топливо 14 910 ₽ (30 л/100 км × 70 ₽/л) + платные 6 390 ₽ (9 ₽/км) +
обслуживание 7 100 ₽ (10 ₽/км) + водитель 6 600 ₽ (660 ₽/ч) = **35 000 ₽**;
доход 120 000 ₽ → **85 000 ₽ чистыми, 120 ₽/км, 8 500 ₽/ч**.

## Альтернативы

- *Подключить карты сразу* — запрещено ТЗ; порт готов, Mock заменяем.
- *Стоимости внутри провайдера* — нарушает слой (адаптерам понадобились бы
  настройки) и дублирует тарифы в каждом провайдере.
- *Расширять старый sync-подбор* — реальные провайдеры асинхронны; ломать
  API один раз сейчас дешевле, чем на живых картах.

## Последствия

(+) Экономика прозрачна (разбивка в explanation и уведомлении), тарифы и веса
— настройки пользователя; провайдеры карт встанут за порт без изменения
движка; решения хранят дистанцию — база для обучения ₽/км.
(−) Тарифы и веса читаются снапшотом при сборке — живое применение новых
настроек подключается через SettingsService/CommandBus. Production providers
и persistent route cache реализованы отдельно в ADR-0027.
