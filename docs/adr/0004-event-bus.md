# ADR-0004: Собственный типизированный EventBus

- **Статус:** Принято
- **Дата:** 2026-07-31

## Контекст

Сервисы порождают факты (статус Telegram изменился, уведомление отправлено,
ошибка), о которых должны узнавать несколько потребителей (статус-бар, дашборд,
журнал) — без прямых ссылок сервис → UI.

## Решение

Собственный in-process EventBus (~100 строк): события — frozen dataclasses в
`core/events`; `subscribe(EventType, handler)` / `publish(event)`; ошибка
подписчика логируется и не мешает остальным. ViewModel'и подписываются и
транслируют в Qt-сигналы.

## Альтернативы

- **Qt-сигналы повсюду** — привязывают ядро и сервисы к Qt: ломается чистота ядра
  и переносимость логики.
- **Прямые вызовы сервис → ViewModel** — жёсткая связность, невозможно добавить
  потребителя без правки сервиса.
- **Сторонние шины (blinker и т.п.)** — нет типизации по классам событий; своя
  реализация тривиальна и полностью под контролем.

## Последствия

(+) Слабая связность, лёгкое добавление потребителей, события = документация фактов.
(−) Ещё одна абстракция; поток данных чуть менее очевиден — компенсируется
типизацией и журналом.
