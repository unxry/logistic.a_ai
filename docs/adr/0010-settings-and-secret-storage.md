# ADR-0010: Хранение настроек и секретов

- **Статус:** Принято
- **Дата:** 2026-07-31

## Контекст

Нужен надёжный фундамент настроек до Telegram-этапа: куда безопасно положить
Bot Token, как не потерять настройки пользователя при сбое, как эволюционировать
схему. Плюс профили транспорта (этап 1.5) должны где-то жить до появления SQLite.

## Решение

1. **JSON-файл** `settings.json` в `~/Library/Application Support/LogistAI/`
   (platformdirs; Windows — AppData тем же кодом).
2. **Атомарная запись**: tmp-файл в том же каталоге → `os.replace` —
   настройки не могут остаться полузаписанными.
3. **Карантин вместо потери**: повреждённый/несовместимый файл переименовывается
   в `settings.broken-<время>.json`, приложение продолжает на дефолтах,
   публикуется `ErrorOccurred`. Данные пользователя не удаляются никогда.
4. **Версия схемы + миграции**: `schema_version` в файле; движок миграций —
   цепочка чистых функций `dict → dict` (каждая обязана поднять версию ровно
   на 1, проверяется). Файл новее приложения — отказ (карантин), не «тихая порча».
5. **Толерантный парсинг**: мусор в поле → дефолт этого поля; битый профиль
   транспорта → пропускается. Настройки не могут «уронить» запуск.
6. **Секреты — только в Keychain** (`KeyringSecretStore`, библиотека keyring;
   Windows Credential Manager тем же кодом). В JSON секретов нет по построению:
   сериализатор просто не знает о токенах. `NullSecretStore` (память) — для
   тестов и осознанного деградированного режима.
7. **Профили транспорта в настройках** (`vehicle.profiles` + активный id) —
   для единиц машин JSON достаточен; полноценный репозиторий в SQLite появится
   вместе со слоем хранения журнала.
8. **Изменения — только командой** `SaveSettings` (CommandBus): секрет
   применяется до записи файла; если Keychain недоступен — настройки не
   перезаписываются.

## Альтернативы

- QSettings — привязка к Qt, плохо тестируется, нет миграций/карантина.
- SQLite для настроек — тяжелее diff/бэкап руками, JSON человекочитаем.
- Секреты в JSON с «шифрованием» — ключ негде хранить, кроме Keychain (велосипед).

## Последствия

(+) Настройки неубиваемы (атомарность+карантин), схема эволюционирует, секреты
под защитой ОС, всё покрыто тестами на tmp_path без реального Keychain.
(−) Транзакции между Keychain и файлом нет — при сбое между шагами возможен
обновлённый токен при старых настройках (документировано; порядок выбран так,
чтобы настройки не перезаписывались при недоступном Keychain).
