# ADR-0005: CommandBus для всех мутаций

- **Статус:** Принято
- **Дата:** 2026-07-31

## Контекст

С ростом функций (FindCargo, AnalyzeCargo, RefreshSources, бэкапы) прямые вызовы
между сервисами множатся и связность растёт. Нужен единый вход для действий,
сквозной аудит и симметрия с EventBus.

## Решение

CommandBus рядом с EventBus (`app/buses`): команды — frozen dataclasses в
`core/commands`; ровно один обработчик на тип (`register`), `await dispatch(cmd)`;
middleware логирует каждую команду с таймингом (аудит в журнале).

Правило потоков: **изменения — команды, факты — события, чтение — query-методы
сервисов**. Прямые вызовы сервис → сервис для мутаций запрещены.

## Альтернативы

- **Прямые вызовы методов сервисов** — проще на старте, но связность растёт с каждым
  модулем, нет единой точки аудита/политик (retry, транзакции — в будущем).
- **Полный CQRS с отдельными read-моделями** — избыточен для desktop-приложения.

## Последствия

(+) Развязка модулей, аудит действий бесплатно, новые операции = команда + обработчик.
(−) Больше классов; для тривиальных действий выглядит церемонно — читаемость
поддерживается рецептом в ARCHITECTURE.md.
